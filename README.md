## Overview

Digital payment ecosystems process millions of transactions every day, and a tiny fraction of them are fraudulent — rare, evolving, and easy to miss in the noise. South Africa's 2023 FATF greylisting made stronger transaction monitoring a national priority for every financial institution in the country.

**ForensIQ** is a prototype that goes beyond a simple fraud alert. It analyses transaction-level data, flags suspicious activity, **explains why** each transaction was flagged, and turns those explanations into recommendations a bank can act on.

This is a hackathon prototype, not a production system — the goal is to prove the approach, not ship a finished platform.

## Problem Statement

> Using transaction-level data, build a system that identifies potentially fraudulent transactions and explains what makes flagged transactions anomalous. Build a classifier that identifies fraudulent transactions, and present how your findings are essential for a banking institution.

Financial institutions need tools that don't just detect suspicious transactions but also explain *why* they were flagged, while keeping false alarms low enough that investigators can act on every alert.

## Dataset

- **Source:** synthetic mobile money transactions generated by a simulation engine calibrated against real African financial services data (the PaySim dataset).
- **Size:** ~630,000 transactions — a stratified 10% sample of the full 6,362,620-row dataset — preserving the real-world fraud rate of **0.13%**.
- **Features:** transaction type, amount, origin balance (before/after), destination balance (before/after), and an existing rule-based fraud flag.

The raw dataset is not committed to this repository due to its size. See [Getting Started](#getting-started) for how to source it.

## Key Findings

Verified against the full dataset during exploratory analysis:

| Finding | Fraudulent | Legitimate |
|---|---|---|
| Fraud only occurs in `TRANSFER` and `CASH_OUT` transactions | — | `PAYMENT`, `CASH_IN`, `DEBIT` are never fraudulent |
| **Rule 1 — Full Balance Drain**: transaction amount exactly equals the sender's opening balance | 97.8% | ~0% |
| **Rule 2 — Frozen Destination Balance**: receiving account shows a zero balance before *and* after the transfer | 49.6% | 0.06% |
| The dataset's built-in rule-based flag (`isFlaggedFraud`) catches | 16 of 8,213 known frauds (0.2% recall) | — |

That last figure is the core motivation for this project: a simple rule-based flag misses over 99.8% of fraud. ForensIQ is built to close that gap.

## Approach

```
Upload Dataset → Explore Data → Engineer Features → Train AI Model
→ Detect Fraud → Explain Findings → Generate Business Insights
```

1. **Explore the data** — distributions of key variables, patterns that separate fraud from non-fraud, and a summary of the most interesting findings.
2. **Detect fraud** — engineered features (including the balance-drain and frozen-destination signals above), a trained classifier, and evaluation using metrics beyond accuracy (precision, recall, PR-AUC) given the extreme class imbalance.
3. **Recommend** — what the bank should do with the findings, which transaction types need the most attention, and the cost trade-off between missed fraud and false alarms.

## Getting Started

1. Clone the repository:
   ```bash
   git clone https://github.com/<your-org>/forensiq.git
   cd forensiq
   ```
2. Create an environment and install dependencies:
   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   ```
3. Place the competition dataset (`dataset.csv`) in a local `data/` folder (not committed).
4. Launch the notebook:
   ```bash
   jupyter notebook notebook/ForensIQ_EDA_Modelling.ipynb
   ```
